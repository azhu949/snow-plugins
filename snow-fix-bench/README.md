# 修复工作台（snow-fix-bench）

Snow App **客户端脚本插件**（脚本插件 / `.user.js`）：通过聊天输入框工具栏的扳手入口打开浮层工作台，完成「代码审查 → issue 跟踪 → 批量修复 → 结果清理」的闭环。

## 形态说明

- 这是**脚本插件**，不是面板插件：在「插件 → 插件列表 → 脚本插件」中安装、启停与编辑，不经过 `config-set scope=plugins`。
- 单文件产物 `dist/snow-fix-bench.user.js`，元数据头声明 `@snow-target client`、`@snow-scope global`，运行在默认沙箱档，数据经 `snow.metadata` / `snow.write`。
- 存储容错：读取失败会暂停写入；数据损坏时先把原始内容备份到 `<key>:corrupt` 再以空数据启动，备份失败同样暂停写入。脚本能捕获序列化与同步写入异常，但宿主 preload 的 `GM_setValue` 仍可能在内部吞掉 IPC / SQLite 错误，这类异步失败脚本层无法感知。
- 界面由脚本自建：入口是聊天输入框工具栏左组里 yolo 徽章右侧的扳手按钮（`.input-toolbar .toolbar-left`；未开启 yolo 时排在左组末尾），工具栏不渲染时回退到宿主动作插槽 `chat.input.actions` 保证入口不丢；点击切换固定浮层工作台显隐，点击浮层外部自动收起；关闭浮层不会停止审查 / 修复会话跟踪。入口只用 DOM 注入一次，只在按钮被宿主重渲染挤出容器或 yolo 徽章切换时校正锚点，不跟随 React 重排反复移动节点；点击走 document 捕获委托，避免宿主重渲染吞掉 click。
- 脚本插件能力边界：不提供项目文件目录树；Git 变更范围来自 `git` 元数据域（文件与状态）。提交记录完全自动获取，无需手动触发：沙箱档读不到 React 内部属性，打开审查弹窗时自动在项目目录执行一次**固定、只读**的 `git log`（经 `mcpSecrets` 隐私域调用宿主内置终端工具），结果直接填入提交分区，失败也不弹提示，只在分区内留一行说明。工具名先传 native 内部全名 `bash-terminal-execute`（`mcpTools.call` 只认这种 `{server_id}-{tool_name}` 形式），被拒时回退到渲染层公开名 `mcp__bash__terminal-execute`；两者都不可用则提示在 MCP 面板为当前项目启用 Terminal（bash）。选中提交后提示词附带 hash / 标题 / 作者 / 日期，由 AI 只读执行 `git show`；文件变更则把清单交给 AI，由 AI 读取文件并执行 `git diff`。issue 与界面开关保存在脚本私有 `GM_*` 存储（按项目隔离）。
- 元数据头声明 `@snow-privacy conversations, messages, git, mcpSecrets`。`mcpSecrets` 仅用于上面这条固定只读 `git log` 通道：脚本不接收用户输入的命令，也不通过终端执行写操作；它是提交记录功能的必需权限，删除后提交记录不可用。
- 脚本自身会通过 `snow.write` 写会话（创建 / 归档 / 删除 / 激活）、切换项目、打开文件，并通过 `GM_*` 保存 issue 与界面状态；除此之外不修改项目文件。
- 不读取 API 密钥、不联网、不执行 Git 写操作。

## 功能

- 浮层内为双栏工作台：左栏是项目树（按合集分组；合集行带 Library 图标、颜色点与成员数；默认只展开当前项目所在合集，其余合集折叠，点击合集行展开 / 收起；当前项目高亮，点击切换项目），右栏展示流程条与 issue 列表。浮层高度限制在 620px 以内，拖动标题栏可移动位置，双击标题栏恢复居中。入口只有一个：聊天输入框工具栏里、yolo 徽章右侧的扳手图标。点击浮层外部会收起工作台；浮层内弹窗打开时外部点击交给弹窗处理，不会连带关闭工作台。
- 流程条（审查 / 提取 / 修复 / 清理）+ 项目 issue 列表（严重度筛选、勾选批量修复、批量删除（含已归档项）、归档 / 删除 / 恢复）。
- 审查：复用与宿主内置 `/review` 相同的范围选择（已暂存 / 工作区 / 提交记录；提交记录来自只读 `git log` 命令）与审查提示词规则，追加 `snow-issues` 结构化输出契约；宿主未向脚本插件开放内置审查面板的调用入口，因此范围选择 UI 由脚本自建，规则与内置 `/review` 对齐。审查消息以宿主官方 `@@review:` 标签发送，会话中显示为审查 chip，后端发送时展开为完整提示词。新建会话自动执行并自动切换到该会话，脚本只读跟踪，完成后解析 issue（仅「严重 / 一般」入库，重复项按 文件路径+标题 指纹去重，忽略行号位移）。
- 修复：勾选 issue 新建会话，按内置批量修复流程（逐条取证 → 并行只读取证 → 冲突分析 → 最小范围实施 → 统一验证）提示词执行，AI 以 `snow-fix-results` 回报，脚本自动回写状态：`fixed` 记为「已修复」，`not_found`（复核后问题不存在或已失效）记为「不存在」，`blocked` 保持「待修复」，不再把未改动代码的取证结论混同为已修复。同一 issue 正在修复，或旧修复会话可能仍在运行且与新选择落在同一文件时，会拒绝新建会话；不同文件的修复仍可并行。本轮 issue 超过并行上限时按上限拆批：当前批次完成后自动新建会话继续下一批，新会话创建后都会自动切换过去，队列与批次进度随项目状态持久化，重连后仍可继续。
- 清理：修复完成后在对话框中确认，归档或删除 issue，归档 / 删除 / 保留对应会话。清理列表展示全部未归档 issue，修复中或待修复项也可勾选删除；主列表的「删除选中项」与单条删除走同一套确认与持久化逻辑。会话按「审查 / 修复」两类整批处理：修复按并行上限分批时每一批都会记入会话台账并一并归档 / 删除，历史上已被新会话取代的审查 / 修复会话同样会列出（即使当前没有跟踪中的会话）。单个会话删除失败不会阻断其余会话与 issue 的处理，失败结果会在提示中给出。清理前会用宿主 runtime 快照核对全部待处理会话（含历史台账）的运行状态：仍在运行的会话拒绝归档 / 删除；无法确认运行状态时，需要在对话框中显式勾选确认后才能继续。
- 设置：右上角齿轮打开设置。并行上限（默认 3，范围 1 - 10）同时决定单个修复会话处理的 issue 条数与提示词中的并行取证 / 并行实施上限；另有「审查完成后自动开始修复」（默认关闭，显式开启后才生效）与「全部修复完成后自动清理」（默认关闭）两个开关，以及自动清理动作（归档 / 删除）。自动修复只处理本次审查新增或重开的 issue；自动清理处理本轮已修复或已确认不存在的 issue 与本轮全部修复会话。设置保存在脚本私有全局存储，切换项目后仍然生效。
- 断线恢复：重新载入工作台并恢复会话跟踪时，如果宿主中已不存在该会话（消息域连续为空），脚本判定会话缺失、停止跟踪并释放修复中状态，避免 issue 永久卡在 fixing。跟踪不设固定总时长：只有出现新的 token、新的消息行或新一轮 run 才算进展，出现进展就继续等待并回写结果；连续 20 分钟（修复为 30 分钟）没有任何可观测进展即停止等待，宿主持续报告运行中但没有新 token / 新消息时同样适用；runtime 域不可读时无法观察运行状态，改为连续 60 分钟无进展才停止，避免长构建 / 长测试被误判。另设 4 小时（修复 8 小时）绝对上限兜住永久挂起。手动停止跟踪或跟踪报错后，活动卡片会随会话状态一起保留（重新打开工作台仍可见；用户点「关闭」后不再重建）：卡片上的「继续跟踪」会把会话状态恢复为运行中并重新挂接轮询，「重新解析」则直接读取最后一条回复重新写入结果。

## 工程化结构

```text
snow-fix-bench/
  src/               源码（多模块）
    constants.js     常量与文案兜底
    settings.js      脚本级设置归一化（并行上限）
    util.js          通用纯函数
    parse.js         snow-issues / snow-fix-results 解析
    issues.js        issue 合并、状态、筛选
    prompts.js       审查 / 修复提示词（中英文）
    store.js         状态仓库
    engine.js        引擎（项目列表、Git 状态与提交读取、会话跟踪、清理动作）
    script/          脚本装载层（api.js 适配 snow/GM，main.js 聊天输入框入口与浮层）
    ui/              host.js / components.js / dialogs.js / panel.js（内置 Preact）
  build.mjs          esbuild 打包脚本（IIFE + UserScript 元数据头 + 内联样式）
  test/              node --test 纯函数单测
  dist/snow-fix-bench.user.js   构建产物（安装到脚本插件的就是它）
  locales/           zh-CN / zh-TW / en 语言包（构建时打入脚本）
  style.css          工作台样式（构建时内联）
```

## 开发

```powershell
npm install        # 安装 esbuild 与 preact
npm run build      # src → dist/snow-fix-bench.user.js
npm run check      # node --check dist/snow-fix-bench.user.js
npm test           # 纯函数单元测试
```

安装 / 更新到本机：

```text
config-set scope=userscripts key="new" value={sourcePath: "D:/ai-workspace/snow-plugins/snow-fix-bench/dist/snow-fix-bench.user.js"}
```

更新已安装脚本时传入已有 scriptId；也可以直接在「插件 → 插件列表 → 脚本插件」中编辑或重新导入 `.user.js`。脚本保存后立即生效，无需重启应用；浮层代码更新后建议关闭再打开工作台。

## 分发

脚本插件以单个 `.user.js` 分发，可从链接安装，也兼容插件市场的 `kind=script` 条目；不再使用面板插件的目录包与 `pack.ps1`。产物在 UserScript 元数据头后内联 Preact 的 MIT 许可声明；本目录另附 `LICENSE` 与 `THIRD-PARTY-NOTICES.md`，构建时会校验产物包含许可声明。
